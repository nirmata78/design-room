Requirements · functional

FR1 · Find

Select scenarios by tags and save them as an immutable, versioned set.

FR2 · Run

Run a build on a set; results per scenario and metric, reusing whatever is unchanged.

Compare a release candidate with the last release on the gate set and answer pass or block.

Theory · what it is

A function from pinned inputs to outputs, run millions of times

It is

Running new code on recorded inputs as a pure function, so outputs can be reused and compared.

Not a batch cluster

A batch cluster runs jobs; it does not promise that two runs agree.

Not CI tests

Unit tests assert; a replay measures thousands of metrics and compares distributions.

Not production shadowing

Shadowing sees today's traffic; replay asks what a new build would do on yesterday's.

How it is builtLogs are cut into one-minute MCAP chunks with a per-topic index, each named by its SHA-256. Workers read by byte range and verify the hash.
OptionWhy it is chosen, or why not
MCAP files on GCS, one-minute chunksHashed chunks make a manifest a list of hashes; byte-range reads fetch one topic without a copy.
HDFS or a shared file systemAnother 20 PB system to run, and a copy per job.
Logs in a databaseFrames are blobs: more cost, a second truth, no byte ranges.
