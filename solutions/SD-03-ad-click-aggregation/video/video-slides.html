Theory · the central tension

Answer sooner, or answer right

Answer sooner

Count as events arrive: fresh, but duplicates and late events are still coming. Provisional.

Answer right

Wait until the hour is complete and count everything once: exact, but two days late.

Do both, from one log

The same code, run twice over the same immutable events. The fast run converges to the right one.

Theory · mechanism M1

Idempotency by event ID

Protects

S1: once.

How it works

The SDK or ad server mints an ID when the event happens. Every later stage keeps the first copy of each ID and drops the rest.

Rules out

A retry, a redelivery or a replay counted twice.

Costs

An ID minted upstream; state per ID for the dedup window.

Theory · mechanism M2

Event time, with watermarks

Protects

S2: the right hour. L2: fresh.

How it works

Count by the time in the event. A watermark says “nothing older is still coming”; a window fires when it passes, early results before.

Rules out

A late or replayed event landing in the hour it arrived.

Costs

Waiting; state for open windows; a cutoff, after which late events become corrections.
