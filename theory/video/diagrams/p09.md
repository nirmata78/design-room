# Part 9 · diagram specifications

Seven figures, two sessions (four and three). Rules: `diagrams/README.md`.

## p9-hit-curve
- **Kind:** line chart, canvas 1600 × 680. X axis "hit ratio" from 80% (left) to 100% (right);
  Y axis "database reads/s" 0 to 200,000.
- Curve: load = (1 − h) × 1,000,000 (a straight line falling to 0 at 100%; draw it and label points
  99% → 10k, 95% → 50k, 90% → 100k).
- Dashed horizontal line at 20,000 "database capacity"; the crossing at 98% marked (**highlight**)
  "overloaded below 98%".

## p9-ttl-sync
- **Kind:** bar chart over time, canvas 1600 × 600. X axis 09:00 to 12:00.
- Low baseline of misses; tall red spikes at 10:00 and 11:00 labelled "10,000 keys expire in one
  second".
- An overlay in green (second series) showing the same keys with ±10% jitter: a low hump spread
  10:54–11:06. Legend: "no jitter" / "jitter ±10%".

## p9-lost-invalidation
- **Kind:** Seq, canvas 1600 × 640. Participants `Writer`, `Database`, `Cache`, `Reader`.
- 1. Writer → DB "price = 19 · commit". 2. note over Writer "crash" (red). 3. dashed Writer → Cache
  "delete price" with a cross. 4. Reader → Cache "get price" → "25" (**highlight**, red). Note:
  "stale until TTL (1 h)".

## p9-stale-set
- **Kind:** Seq, canvas 1600 × 780. Participants `Reader A`, `Cache`, `Database`, `Writer`.
- 1. A → Cache "get k → miss". 2. A → DB "read k → v1". 3. note on A "slow…". 4. Writer → DB
  "k = v2". 5. Writer → Cache "delete k". 6. A → Cache "set k = v1" (**highlight**, red). Note:
  "old value cached after the invalidation".

## p9-lease
- **Kind:** Seq, same participants as p9-stale-set, canvas 1600 × 780.
- 1. A → Cache "get k" → "miss · lease 77". 2. A → DB "read → v1". 3. Writer → DB "k = v2".
  4. Writer → Cache "delete k (voids lease 77)". 5. A → Cache "set k = v1 · lease 77" → "refused"
  (**highlight**, green cross). 6. Reader B → Cache "get k" → "miss · lease 78" → loads v2.

## p9-tiers
- **Kind:** funnel, canvas 1600 × 720.
- `100k req/s` entering `in-process cache (µs, thousands of keys)` → "60% served" ; `40k` →
  `remote cache cluster (0.5 ms, millions)` → "98% of the rest" ; `800/s` → `database`.
- Side note on the in-process tier (**highlight**): "hard to invalidate · TTL seconds".

## p9-penetration
- **Kind:** block diagram, canvas 1600 × 680.
- `Client: random ids, 50k/s` → `Bloom filter of existing ids` → (green "maybe") `Cache` →
  (miss) `Database`.
- From the filter a red arrow back to the client "definitely absent → 404 at once" (**highlight**).
- From the cache a small box "negative entry: id 9931 → not found · TTL 30 s".
