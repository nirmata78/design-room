# Part 8 · diagram specifications

Thirteen figures, three sessions (five, four, four). Most are small Seq diagrams. Rules:
`diagrams/README.md`.

## p8-lost-update
- **Kind:** Seq, canvas 1600 × 640. Participants `T1`, `Database (counter = 42)`, `T2`.
- 1. T1 → DB "read → 42". 2. T2 → DB "read → 42". 3. T1 → DB "write 43 · commit". 4. T2 → DB
  "write 43 · commit" (**highlight**, red). Note at bottom: "two increments · counter moved by one".

## p8-two-editors
- **Kind:** Seq, canvas 1600 × 640. Participants `Ana`, `Docs service (v7)`, `Ben`.
- 1. Ana "load v7". 2. Ben "load v7". 3. Ana "save → v8". 4. Ben "save (based on v7)" →
  note "overwrites Ana's change silently" (**highlight**, red).

## p8-deadlock
- **Kind:** cycle diagram, canvas 1600 × 640.
- Two transaction circles `T1: A → B` and `T2: B → A`; two row boxes `row A`, `row B`.
- Solid arrows "holds": T1 → row A, T2 → row B. Dashed red arrows "waits for": T1 → row B, T2 →
  row A, forming a cycle (**highlight**). Caption: "database aborts one · fix: lock lower id first".

## p8-partial-commit
- **Kind:** Seq, canvas 1600 × 640. Participants `Transfer service`, `Shard 1 (account A)`,
  `Shard 2 (account B)`.
- 1. Service → S1 "debit 30 · commit ✓". 2. note over Service "crash" (red). 3. dashed Service → S2
  "credit 30" with a cross (**highlight**). Note: "30 left A, arrived nowhere".

## p8-2pc
- **Kind:** Seq, canvas 1600 × 820. Participants `Coordinator`, `Shard 1`, `Shard 2`.
- Phase band 1 "prepare": 1. C → S1 "prepare". 2. C → S2 "prepare". 3. note on both shards "write
  prepared state durably · keep locks". 4. S1 → C "yes". 5. S2 → C "yes".
- Phase band 2 "commit": 6. note on C (**highlight**) "log COMMIT ← decision point". 7. C → S1
  "commit". 8. C → S2 "commit". 9. note "release locks".

## p8-2pc-blocked
- **Kind:** Seq, canvas 1600 × 720. Same participants.
- 1–5 as in p8-2pc (prepare, yes, yes). 6. red cross on the Coordinator lifeline "crashes before
  sending decision". 7. long amber bars on both shard lifelines (**highlight**) "in doubt · locks
  held · cannot decide alone". 8. a `Client` box at the side "waits on the locked rows".

## p8-2pc-paxos
- **Kind:** block diagram, canvas 1600 × 760.
- Three dashed group boxes, each containing three replica circles with one marked leader:
  `Group A (coordinator)`, `Group B (participant)`, `Group C (participant)`.
- Arrows from A's leader to B's and C's leaders "prepare". Inside B and C, small arrows leader →
  replicas "prepare record via consensus". Inside A "commit record via consensus" (**highlight**).
- One replica of A crossed out with a note "leader lost → new leader reads decision from log".

## p8-saga-fail
- **Kind:** three boxes in a row, canvas 1600 × 560: `Flight ✓ booked`, `Hotel ✓ booked`,
  `Car ✗ failed` (red). Caption: "no shared transaction · two real bookings to undo".

## p8-saga
- **Kind:** block diagram, canvas 1600 × 780.
- `Orchestrator` with a small log strip "saga s-81: step 1 done, step 2 done, step 3 failed".
- Forward row: `① book flight` → `② book hotel` → `③ book car ✗`.
- Return row (red arrows, right to left, **highlight**): `cancel hotel` ← `cancel flight`.
- Note: "every step and compensation idempotent, keyed by saga id".

## p8-double-click
- **Kind:** Seq, canvas 1600 × 720. Participants `Browser`, `API (req 1)`, `API (req 2)`,
  `Key table`, `Card network`.
- 1. Browser → req1 "POST /pay · key k1". 2. Browser → req2 "POST /pay · key k1 (+50 ms)".
  3. req1 → Key table "k1? → absent". 4. req2 → Key table "k1? → absent" (**highlight**).
  5. req1 → Card "charge". 6. req2 → Card "charge" (red). Note: "check then act, in two steps".

## p8-oversell
- **Kind:** block diagram, canvas 1600 × 560.
- Many small user icons (label "100 users") with arrows to one `seat 12` box; three arrows continue
  to a `payments` box marked "paid ×3" (**highlight**, red). Caption: "two systems, no shared
  transaction".

## p8-reservation
- **Kind:** Seq, canvas 1600 × 820. Participants `User`, `Booking`, `Inventory`, `Payments`.
- 1. Booking → Inventory "① hold seat 12 · hold h7 · until +10 min · if available" → "ok".
  2. Booking → Payments "② charge · idempotency key h7" → "ok". 3. Booking → Inventory "③ confirm:
  sold if held by h7" → "1 row ✓" (**highlight**, green).
- Alternative box at the bottom "else": "hold expired → 0 rows → refund (key h7) · tell user"
  (amber).

## p8-escrow
- **Kind:** block diagram, canvas 1600 × 720.
- Top: `Ledger · budget 10,000 · granted 9,200 · remaining 800`.
- Ten small shard boxes below, each "allowance 1,000" with a local bar partly used (one shows
  "40 left", one shows "0 · asks for more").
- Arrow from an empty shard up to the ledger "request more" and back "grant ≤ remaining"
  (**highlight**).
