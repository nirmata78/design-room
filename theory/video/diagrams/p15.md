# Part 15 · diagram specifications

Eight figures, two sessions (four each). Rules: `diagrams/README.md`.

## p15-planes
- **Kind:** two horizontal bands, canvas 1600 × 760.
- Top band `Control plane · hundreds of changes/s · may be down for minutes`: `API` → `Consistent
  store (desired state)` → `controllers`.
- Bottom band `Data plane · millions of requests/s · local state`: proxies, servers, storage nodes,
  each with a small "last known good" disk icon.
- One-way dashed arrows down "versioned state, pushed". User request arrows enter and leave only
  the bottom band (**highlight**): "nothing on the request path calls the control plane".

## p15-edge
- **Kind:** timeline, canvas 1600 × 620. Lanes `Replicas`, `Events`, `Controller`.
- Replicas: three bars; one ends at t = 5 (red cross).
- Events: "replica died" emitted at t = 5.
- Controller: a grey gap t = 4 to 8 "restarting"; the event arrow falls into the gap and is lost
  (**highlight**). After t = 8 "waiting for events…" and replicas lane shows "2 for ever".

## p15-preempt
- **Kind:** block diagram, canvas 1600 × 700.
- A node box filled with tasks: `batch b1`, `batch b2`, `prod p3`, `prod p4` (full).
- Incoming `prod p9 (high priority, team within quota)`.
- b1 and b2 outlined amber "SIGTERM · 30 s grace · checkpoint" then removed; p9 placed in their
  space (**highlight**); b1, b2 arrows back to a `queue` "requeued".

## p15-partition
- **Kind:** block diagram, canvas 1600 × 720.
- `Control plane` on the left; three zone boxes on the right, zone c containing 200 node dots all
  green "healthy, serving".
- A red jagged line between the control plane and zone c "partition".
- Callout (**highlight**): "200 silent at once → stop evicting · nodes keep running tasks".

## p15-timers
- **Kind:** block diagram, canvas 1600 × 780.
- Left: a `timer store` table with keys `(bucket 00:00, shard 0) … (bucket 00:00, shard 15)` and
  `(bucket 00:01, …)`.
- Middle: 16 small `scheduler shard` boxes, one arrow each "range read at 23:59".
- Right: one shard's `timing wheel` drawn as a circle of 60 slots with a pointer "advance 1 slot/s",
  some slots holding timer dots; a small `heap` box "next due".

## p15-launch-gap
- **Kind:** Seq, canvas 1600 × 700. Participants `Leader 1`, `Worker`, `Store`, `Leader 2`.
- 1. note on Leader 1 "decide: run billing for the 12th". 2. Leader 1 → Worker "start billing".
  3. note on Worker "billing runs". 4. red cross on Leader 1 "crash before recording".
  5. Leader 2 → Store "read: no launch recorded". 6. Leader 2 → Worker "start billing" (**highlight**,
  red). Note: "everyone billed twice".

## p15-lease
- **Kind:** Seq, canvas 1600 × 820. Participants `Leader`, `Store (consensus)`, `Queue`, `Worker`,
  `Downstream`.
- 1. Leader → Store "① launch record: billing/12 · attempt 1 · starting". 2. Leader → Queue "task".
  3. Worker → Queue "② lease task · 60 s" with "heartbeat" loop arrows. 4. Worker → Downstream
  "effect · attempt 1". 5. Worker → Store "③ result · attempt 1 · done".
- Alternative box: "④ lease expires → attempt 2 queued; downstream refuses attempt 1 (fencing)"
  (**highlight**).

## p15-workflow
- **Kind:** two columns, canvas 1600 × 760.
- Left: workflow code lines `charge()`, `sleep(2 days)`, `ship()`, `email()`.
- Right: `event history` list: "1 charge → ok (ch_81)", "2 timer started (2 days)".
- A red cross "worker crash" between the columns; a second worker box "replay from start" with
  arrows: `charge()` → "found in history, not re-run" (green), `sleep` → "resume timer"
  (**highlight**).
