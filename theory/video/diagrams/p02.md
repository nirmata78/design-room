# Part 2 · diagram specifications

Twelve figures, three sessions (four each). Rules: `diagrams/README.md`. "Seq" means a sequence
diagram drawn with `seqsvg`; "timeline" means horizontal lanes with time running left to right,
drawn as plain SVG.

## p2-partition
- **Kind:** block diagram, canvas 1600 × 720.
- Three replica boxes in a row: `Replica 1 · x = 2`, `Replica 2 · x = 2`, `Replica 3 · x = 1`.
- A red dashed vertical line between replica 2 and replica 3, labelled "network partition".
- Light blue background behind replicas 1 and 2, labelled "majority side". Light amber behind
  replica 3, labelled "minority side · healthy, but cut off".
- `Client A` above the majority side with an arrow to replica 1 labelled "write x = 2 ✓".
- `Client B` above replica 3 with an arrow to it labelled "read x ?" (**highlight**).
- Under replica 3, two answer boxes side by side: green-bordered "answer **1** → available, not
  consistent" and red-bordered "refuse → consistent, not available".

## p2-session-anomalies
- **Kind:** two Seq diagrams stacked, canvas 1600 × 860, a thin divider between them.
- **Top, title "No read-your-writes":** participants `User`, `Leader`, `Replica (behind)`.
  1. User → Leader: "post comment". 2. Leader → User: "ok". 3. Leader ⇢ Replica (dashed, slow):
  "replicate… not arrived yet". 4. User → Replica: "reload". 5. Replica → User: "no comment"
  (**highlight**, red).
- **Bottom, title "No monotonic reads":** participants `User`, `Replica A (current)`,
  `Replica B (behind)`. 1. User → Replica A: "refresh". 2. Replica A → User: "3 replies".
  3. User → Replica B: "refresh". 4. Replica B → User: "2 replies" (**highlight**, red).

## p2-lin-vs-ser
- **Kind:** two timelines stacked, canvas 1600 × 780.
- **Top, title "Linearizable · single operations, real-time order":** lane `Client A` with a bar
  "write x = 2" from t = 1 to t = 3. Lane `Client B` with a bar "read x" from t = 4 to t = 5,
  result label "must return 2" (green). A dotted vertical line at t = 3 labelled "write completed".
- **Bottom, title "Serializable · whole transactions, some serial order":** lane `T1` with a bar
  "read A, write B" from t = 1 to t = 4. Lane `T2` with a bar "read B, write A" from t = 2 to t = 5.
  To the right, a box: "result must equal **T1 then T2** or **T2 then T1** · either is allowed ·
  real time is not consulted".

## p2-stale-quorum
- **Kind:** timeline, canvas 1600 × 760. Title "N = 3, W = 2, R = 2".
- Three replica lanes `R1`, `R2`, `R3`, each starting with value "x = 1".
- A writer arrow reaches `R1` at t = 2 (R1 becomes "x = 2", blue); dashed arrows to `R2` and `R3`
  arrive only at t = 8, labelled "still in flight".
- `Reader A` at t = 3: a bracket over R1 and R2, result "sees 2 and 1 → returns **2**".
- `Reader B` at t = 5: a bracket over R2 and R3, result "sees 1 and 1 → returns **1**"
  (**highlight**, red).
- Caption: "B read after A and saw an older value."

## p2-lww-skew
- **Kind:** timeline, canvas 1600 × 720.
- Top axis "true time": ticks 0 ms, 50 ms, 100 ms.
- Lane `Node A · clock 100 ms fast`: event at true 0 ms, "write x = 1 · stamped **100**".
- Lane `Node B · clock correct`: event at true 50 ms, "write x = 2 · stamped **50**".
- Right side, box "last writer wins: 100 > 50 → keep **x = 1**" and below it, in red, "the later
  write is discarded · no error".

## p2-version-vector
- **Kind:** block diagram, canvas 1600 × 720.
- Start box, top centre: "key k · value v0 · vector (1, 0)" with caption "entries: (replica A, replica B)".
- Arrow down-left to box `Replica A`: "client 1 writes v1 · vector **(2, 0)**".
- Arrow down-right to box `Replica B`: "client 2 writes v2 · vector **(1, 1)**".
- Both arrows down to a merge box (**highlight**): "(2, 0) vs (1, 1): each ahead in one position →
  **concurrent** · keep both · merged vector (2, 1)".

## p2-commit-wait
- **Kind:** timeline, canvas 1600 × 700.
- One horizontal axis "true time". Above it, a shaded interval bracket labelled "clock answers:
  [earliest, latest] · true time is somewhere inside".
- Mark `s` at the **latest** edge: "commit timestamp s = latest".
- A hatched bar starting at s, labelled "commit wait · locks held", ending where a second, later
  interval's **earliest** edge passes s; mark that point "earliest > s → report commit" (**highlight**).
- To the right: a second transaction bar starting after that point, labelled "any later
  transaction gets a timestamp > s".

## p2-lost-reply
- **Kind:** Seq, canvas 1600 × 700. Participants `Client`, `Payment service`, `Card network`.
- 1. Client → Service: "POST /pay 20". 2. Service → Card: "charge 20". 3. Card → Service: "ok".
  4. Service → Client: "200 OK" — drawn as a red arrow that stops halfway with a cross, labelled
  "reply lost". 5. Client (self note): "timeout · lost request or lost reply?" 6. Client → Service:
  "POST /pay 20 (retry)". 7. Service → Card: "charge 20" (**highlight**, red). Final note across
  the bottom: "charged twice".

## p2-dedup
- **Kind:** Seq, canvas 1600 × 760. Participants `Client`, `Service`, `Database`.
- 1. Client → Service: "POST /pay · Idempotency-Key: k1". 2. Service → Database: "BEGIN · insert
  key k1 · apply charge · store response · COMMIT" (one arrow, label on two lines; note beside it:
  "one transaction"). 3. Service → Client: "200 OK" lost (red, cross). 4. Client → Service: "POST
  /pay · Idempotency-Key: k1 (retry)". 5. Service → Database: "insert key k1 → already exists"
  (**highlight**). 6. Database → Service: "stored response". 7. Service → Client: "200 OK · the
  original response" (green).

## p2-pause
- **Kind:** timeline, canvas 1600 × 760. Time axis ticks at 0 s, 10 s, 15 s.
- Lane `Client A`: bar "holds lease" from 0 s to 10 s (blue); from about 2 s to 15 s a grey hatched
  overlay "paused · GC or VM migration"; at 15 s an event "wakes · still believes it holds the lock
  · **writes**" (red).
- Lane `Lock service`: event at 0 s "grant to A · lease 10 s"; event at 10 s "lease expired · grant
  to B".
- Lane `Client B`: bar "holds lease · writing" from 10 s onward (blue).
- Lane `Storage`: at about 11 s an arrow from B "write"; at 15 s an arrow from A "write"
  (**highlight**, red); label "two writers".

## p2-fencing
- **Kind:** the same layout as `p2-pause`, canvas 1600 × 760, with tokens.
- Lock service events: "grant to A · token **33**", "grant to B · token **34**".
- Storage lane shows a small state box "highest token seen" changing from 33 to 34.
- B's write arrow labelled "write, token 34 → accepted" (green).
- A's late write arrow labelled "write, token 33 → **rejected**: 33 < 34" (**highlight**, red, ends
  in a cross).

## p2-gossip
- **Kind:** four panels in a row, canvas 1600 × 620, titled "round 0", "round 1", "round 2", "round 3".
- Each panel: the same 16 dots on a 4 × 4 grid. Informed dots are blue, others light grey.
  Round 0: 1 blue. Round 1: 2 blue. Round 2: 4 blue. Round 3: 8 blue. In each panel draw thin
  arrows from each previously informed dot to the dot it informed this round.
- Under the panels: "1 → 2 → 4 → 8 … · 1,000 nodes in about 10 rounds, stragglers a few more".
