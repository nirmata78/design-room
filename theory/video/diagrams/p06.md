# Part 6 · diagram specifications

Eight figures, two sessions (four each). Rules: `diagrams/README.md`.

## p6-hash-range
- **Kind:** two panels, canvas 1600 × 700, titles "Range" and "Hash".
- **Left:** a horizontal key line A … Z cut into four coloured segments `shard 1: A–F`,
  `shard 2: G–M`, `shard 3: N–S`, `shard 4: T–Z`. A bracket over "C … E" labelled "scan → one shard".
- **Right:** the same keys `ann, bob, cat, dan …` each with an arrow through a small `hash()` box
  to one of four shard boxes, arrows crossing. A bracket "scan C … E → every shard" (**highlight**).

## p6-mod-n
- **Kind:** table-like grid, canvas 1600 × 640. 20 columns for keys with hash values 0 … 19.
- Row 1 "4 nodes: h mod 4" with values; row 2 "5 nodes: h mod 5" with values.
- Columns where both equal (h = 0, 1, 2, 3) in green; all others red.
- Caption (**highlight**): "4 of 20 stay · 80% move to add 20% capacity".

## p6-ring
- **Kind:** ring, canvas 1600 × 820. Circle with nodes `A`, `B`, `C`, `D` at 12, 3, 6, 9 o'clock.
- Small key dots around the ring, each coloured by its owner (the next node clockwise).
- New node `E` (red outline) inserted between B and C. The arc from B to E highlighted
  (**highlight**) with label "only these keys move: C → E".
- Caption: "add 1 node to 4 → about 1/5 of keys move".

## p6-split
- **Kind:** block diagram, canvas 1600 × 680.
- Top: one long bar `range A–M · 520 MB · 9k req/s` on `server 3`, with a dashed cut at `G`.
- Arrow down to two bars `A–G` and `G–M`, both still on `server 3` (label "split = metadata only").
- Right: a small table `shard map v21 → v22` showing one row replaced by two.
- Optional dashed arrow from `G–M` to `server 8` labelled "later: balancer moves it".

## p6-move
- **Kind:** Seq, canvas 1600 × 760. Participants `Server 1 (owner)`, `Server 2 (target)`,
  `Shard map`, `Client`.
- 1. S1 → S2: "① snapshot of range (throttled)". 2. S1 → S2: "② stream new writes". 3. Client → S1:
  "write" (continues to succeed). 4. note over S1 (**highlight**): "③ pause writes · drain last
  ones". 5. S1 → Map: "owner = S2 · v23". 6. Client → S1: "write" → reply "moved, v23". 7. Client →
  S2: "write ✓". 8. note over S1: "④ delete copy later".

## p6-routing
- **Kind:** three panels in a row, canvas 1600 × 700, titles "any node forwards", "routing tier",
  "smart client".
- Panel 1: `Client` → `node B` → (forward) `node D (owner)`.
- Panel 2: `Client` → `Router (holds map)` → `node D`.
- Panel 3: `Client (holds map)` → `node D` directly.
- Under all three: one `Coordination service · shard map` box with dashed arrows up to the map
  holders in each panel, labelled "push map".

## p6-indexes
- **Kind:** two panels, canvas 1600 × 760, titles "Local index" and "Global index (by colour)".
- **Left:** three shard boxes, each with a data list and a small index "red → 3, 9" etc. A query
  arrow `colour = red` fanning to all three (**highlight**) and a merge box.
- **Right:** three data shards on top, two index shards below `colours a–m`, `colours n–z`. A write
  to product 7 on shard 2 with a second dashed arrow to index shard `n–z` labelled "async update".
  The query arrow goes only to `n–z`.

## p6-domains
- **Kind:** two panels, canvas 1600 × 760, titles "random" and "domain-aware".
- Each panel: three rack boxes (rack 1, rack 2, rack 3) with 4 machine squares each; zones as dashed
  boxes around racks in the right panel (`zone a`, `zone b`, `zone c`).
- **Left:** three squares labelled `r42` all in rack 1; a red cross on rack 1's switch (**highlight**),
  caption "one switch → range 42 lost".
- **Right:** `r42` once in each zone; the same cross on rack 1; caption "two copies remain".
