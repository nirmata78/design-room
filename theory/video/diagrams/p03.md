# Part 3 · diagram specifications

Seven figures, two sessions. Rules: `diagrams/README.md`. Servers are named `S1` … `S5` throughout.

## p3-smr
- **Kind:** block diagram, canvas 1600 × 720.
- Left: two `Client` boxes with arrows labelled "command" into a wide box `Consensus module`.
- Centre: under it, a horizontal strip `Replicated log` of five cells: "1 · set x=1", "2 · set y=2",
  "3 · del x", "4 · set x=7", "5 · …". A bracket over cells 1–4 labelled "committed".
- Right: three stacked boxes `Replica 1 · state machine`, `Replica 2 · state machine`,
  `Replica 3 · state machine`, each showing the same state "x = 7, y = 2", each with an arrow from
  the log labelled "apply in order".
- Caption: "same log + deterministic apply = same state".

## p3-election
- **Kind:** timeline with five lanes `S1` … `S5`, canvas 1600 × 780.
- Band on the left labelled "term 1": S1 is marked "leader", small arrows "heartbeat" to the others.
- At a point marked with a red cross on S1's lane: "S1 fails".
- Each of S2–S5 has an election-timer bar of a different length starting at the cross (S3's the
  shortest); label the group "random timeouts, 150–300 ms".
- At the end of S3's bar: "S3: term → 2, votes for itself" (**highlight**), then arrows
  "RequestVote (term 2)" from S3 to S2, S4, S5 and replies "vote granted" from S2 and S4.
- Band on the right labelled "term 2": S3 marked "leader · 3 votes of 5", arrows "heartbeat" to
  S2, S4, S5 with a note "timers reset".

## p3-append
- **Kind:** Seq, canvas 1600 × 760. Participants `Client`, `S3 (leader, term 2)`, `S2`, `S4`, `S5`.
- 1. Client → S3: "set x = 7". 2. S3 self: "append at index 5, term 2 · fsync". 3. S3 → S2, S4, S5
  (three arrows, same label): "AppendEntries · prev = (index 4, term 1) · entry 5". 4. S2 self:
  "has (4, 1)? yes · append · fsync". 5. S2 → S3: "ok". 6. S4 → S3: "ok". 7. S3 self (**highlight**):
  "on 3 of 5 → committed · apply". 8. S3 → Client: "ok". 9. S5 → S3: "ok (late)" in grey.
  10. S3 → all: "next message carries commit index 5" in grey.

## p3-figure8
- **Kind:** four panels in a row (a)–(d), canvas 1600 × 760. Each panel shows five short logs,
  rows `S1` … `S5`, columns index 1, 2, 3. A cell shows the **term** of its entry, coloured by term
  (term 1 grey, 2 blue, 3 amber, 4 green). Outline the current leader's row in bold.
- **(a) "term 2 · S1 leads":** all rows have index 1 = term 1. S1 and S2 also have index 2 = term 2.
- **(b) "S1 crashes · S5 wins term 3":** as (a), plus S5 has index 2 = term 3. S5 outlined.
  Caption "votes from S3, S4, S5".
- **(c) "S5 crashes · S1 wins term 4":** S1, S2, S3 have index 2 = term 2; S5 still has index 2 =
  term 3; S1 also has index 3 = term 4. S1 outlined. Red caption (**highlight**): "term-2 entry is
  on 3 of 5 · NOT committed · S5 could still win and overwrite it".
- **(d) "safe":** S1, S2, S3 have index 2 = term 2 and index 3 = term 4. Green caption: "a term-4
  entry is on a majority · S5 can no longer win · both entries committed".

## p3-readindex
- **Kind:** Seq, canvas 1600 × 700. Participants `Client`, `Leader`, `Follower A`, `Follower B`.
- 1. Client → Leader: "read x". 2. Leader self: "note commit index = 41". 3. Leader → Follower A,
  Follower B: "heartbeat (term 7)". 4. Follower A → Leader: "ack" (**highlight**, with note "self +
  A = majority of 3 → still the leader"). 5. Leader self: "wait until applied ≥ 41". 6. Leader →
  Client: "x = 7". Side note: "no log entry, no disk write, one round trip".

## p3-paxos-duel
- **Kind:** Seq, canvas 1600 × 780. Participants `Proposer 1`, `Acceptor A`, `Acceptor B`,
  `Acceptor C`, `Proposer 2`.
- 1. P1 → A, B, C: "prepare(1)". 2. A, B, C → P1: "promise(1), nothing accepted".
  3. P2 → A, B, C: "prepare(2)". 4. A, B, C → P2: "promise(2), nothing accepted".
  5. P1 → A, B, C: "accept(1, X)". 6. A, B, C → P1: "rejected: promised 2" (**highlight**, red).
  7. P2 → A, B, C: "accept(2, Y)". 8. A, B, C → P2: "accepted" (green). Final note: "Y is chosen ·
  P1 retries with ballot 3 and must adopt Y".
- If ten messages do not fit legibly, draw each fan-out as one arrow to a bracket around the three
  acceptors.

## p3-placement
- **Kind:** block diagram, canvas 1600 × 720.
- Three region boxes in a triangle: `Region 1` (top left) containing two voter circles, one marked
  "leader"; `Region 2` (top right) containing two voter circles; `Region 3` (bottom centre)
  containing one voter circle.
- Lines between regions labelled with round trips: Region 1–Region 2 "30 ms", Region 1–Region 3
  "80 ms", Region 2–Region 3 "70 ms".
- Green arrows from the leader: to its local neighbour "≈ 1 ms" and to one voter in Region 2
  "30 ms" (**highlight**). Grey dashed arrow to Region 3 "80 ms · not needed for commit".
- Note box: "majority = 3 of 5 = leader + local + nearest remote → commit ≈ 30 ms".
